# INC-2026-011 - MCP de producción devolvía memoria de prueba cuando faltaba la credencial Supabase y la agenda no paginaba

- Fecha: 2026-10-29
- Flujo critico: R1
- Estado: CORREGIDO

## Impacto

Los agentes MCP autenticados, incluido `ismael.correa@firplak.com` con rol ADMIN, podían recibir cero filas de Supabase y luego consultar los registros sembrados `acc-uuid-1`, `opp-archivada-1` y `opp-otro-vendedor` como si fueran datos reales. Además, `crm_agenda_diaria` devolvía todas las actividades pendientes en una sola respuesta, con riesgo de saturar el contexto del agente.

## Causa raiz

`CrmDatabaseAdapter` usaba `NEXT_PUBLIC_SUPABASE_ANON_KEY` cuando `SUPABASE_SERVICE_ROLE_KEY` no estaba disponible. Las herramientas no reenviaban el JWT del usuario al cliente de datos, por lo que RLS ejecutaba las consultas como `anon` y podía devolver cero filas sin error. Ante una configuración ausente o un error de consulta, cada herramienta caía silenciosamente al almacén de memoria sembrado para pruebas. La agenda tampoco aceptaba `limit` ni `offset`.

## Prevencion

El adaptador exige `SUPABASE_SERVICE_ROLE_KEY` para operaciones MCP fuera de pruebas. El fallback de memoria queda limitado a `NODE_ENV=test` o al opt-in explícito `MCP_ALLOW_MEMORY_FALLBACK=true`; cualquier fallo de configuración o consulta retorna un error visible. El despachador aplica la misma guarda a HTTP y stdio. `crm_agenda_diaria` ahora limita la respuesta a 10 filas por defecto, máximo 30, y expone `total_count`, `limit`, `offset` y `has_more`.

## Deteccion permanente

- Prueba que falla antes de la correccion: `tests/crm-mcp.test.ts`, bloque `15. Producción fail-closed y consultas acotadas`.
- Etapa QA que la ejecuta: `focused-tests` mediante `npm run qa:focused -- tests/crm-mcp.test.ts tests/mcp-auth.test.ts tests/mcp-token.test.ts`.
- Identidad estable del caso: `no devuelve datos de memoria cuando falta SUPABASE_SERVICE_ROLE_KEY en producción` y `pagina la agenda diaria y reporta el total sin devolver toda la agenda`.

- GREEN: 36/36 pruebas MCP, artefacto `.tmp/qa-results/2026-10-29T16-01-52-846Z-focused`.

## Riesgo residual

Resuelto el 2026-10-29: con la CLI autenticada en la cuenta `analistadesarrollador-8356` (equipo `firplaks-projects`) se confirmó que `SUPABASE_SERVICE_ROLE_KEY` no existía en el proyecto `crm-64yu`. Se agregó como variable Sensitive en Production y Preview, se redesplegaron ambos entornos y se verificó en producción: `POST /api/mcp/personal-token` con token inválido devuelve `401` de sesión en lugar del error de credenciales de Supabase. Pendiente de confirmación funcional: una generación real del token `mcp_pat_` desde la sesión del CRM y una consulta end-to-end desde el bot de Ismael.

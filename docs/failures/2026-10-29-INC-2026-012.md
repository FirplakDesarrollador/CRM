# INC-2026-012 - Token MCP de sesión expiraba y rompía automatizaciones programadas

- Fecha: 2026-10-29
- Flujo critico: R1
- Estado: CORREGIDO

## Impacto

Los bots conectados al MCP, incluido el de `ismael.correa@firplak.com`, dependían exclusivamente del JWT de sesión de Supabase. Al expirar aproximadamente una hora después, reportes y automatizaciones programadas recibían `401` aunque el usuario continuara activo y autorizado.

## Causa raiz

La interfaz copiaba directamente `session.access_token` y el endpoint solo validaba tokens mediante `auth.getUser(token)`. No existía una credencial MCP durable, revocable y vinculada a la identidad del usuario.

## Prevencion

Se añadió un token personal `mcp_pat_<userId>.<secreto>` con 256 bits aleatorios y sin expiración. El servidor almacena exclusivamente su hash SHA-256 en `auth.users.app_metadata`, lo valida en tiempo constante y resuelve el rol vigente desde `CRM_Usuarios`. Regenerar el token reemplaza el hash y revoca el anterior. La service role nunca se expone al cliente.

## Deteccion permanente

- Prueba que falla antes de la correccion: `tests/mcp-auth.test.ts` y `tests/mcp-token.test.ts`.
- Etapa QA que la ejecuta: `focused-tests` mediante `npm run qa:focused -- tests/mcp-auth.test.ts tests/mcp-token.test.ts tests/crm-mcp.test.ts`.
- Identidad estable del caso: `autentica el token personal cuando su hash coincide en app_metadata`, `rechaza un token personal alterado o revocado` e `intercambia una sesión vigente por un token MCP permanente`.

## Evidencia

- RED: import inexistente y autenticación personal rechazada, artefactos `.tmp/qa-results/2026-10-29T16-12-31-284Z-focused` y `.tmp/qa-results/2026-10-29T16-12-50-922Z-focused`.
- GREEN: 41/41 pruebas MCP, artefacto `.tmp/qa-results/2026-10-29T16-14-11-962Z-focused`.
- Implementación: `lib/mcp/personal-token.ts`, `lib/mcp/auth.ts`, `app/api/mcp/personal-token/route.ts`, `components/config/McpIntegrationCard.tsx`.

## Riesgo residual

Después del despliegue, cada usuario debe generar su token personal desde Configuración y sustituir el JWT anterior en su bot. No se migra ni conserva el token de sesión expirado.

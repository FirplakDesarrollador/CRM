# INC-2026-013 - Leads web guardados como Consumidor Final aunque vTiger trae el nombre

- Fecha: 2026-11-03
- Flujo critico: R7
- Estado: CORREGIDO

## Impacto

Leads de la web (p. ej. teléfono 3162572644 / Caralina) se creaban en CRM como cuenta, contacto y oportunidad **Consumidor Final** aunque vTiger tenía el apellido real (`Caralina`) y la oportunidad `Por definir`. El asesor no podía identificar al cliente.

## Causa raiz

`wordpress-lead-intake` leía solo `body.contacto.nombre`. Si venía vacío, `-` o el propio fallback, y el nombre real iba en `apellido`/`lastname` (mapeo típico a vTiger), se persistía `Consumidor Final`. `Por definir` se copiaba como nombre de cuenta.

## Prevencion

`resolveLeadPersonName` concatena nombre+apellido (incl. firstname/lastname) e ignora placeholders. `Por definir` usa el nombre de la persona. Si ya existe una cuenta placeholder y llega un nombre real, se corrige cuenta, contacto y oportunidad abierta.

## Deteccion permanente

- Prueba que falla antes de la correccion: `tests/leadDeduplication.test.ts` casos de nombre de lead web.
- Etapa QA que la ejecuta: `focused-tests` mediante `npm run qa:focused -- tests/leadDeduplication.test.ts`.
- Identidad estable del caso: `usa apellido/lastname de vTiger cuando nombre viene vacío, guion o Consumidor Final` y `la Edge Function de WordPress usa el resolver de nombre y no solo contacto.nombre`.

## Evidencia

- RED: 5 fallos por helpers inexistentes y Edge Function sin resolver, artefacto `.tmp/qa-results/2026-11-03T20-51-09-821Z-focused`.
- GREEN: 10/10, artefacto `.tmp/qa-results/2026-11-03T20-52-11-392Z-focused`.
- Datos: oportunidad `866dfcbd-fd10-4f32-b8c2-cfea43d93487` renombrada a Caralina en producción.

## Riesgo residual

La Edge Function de producción debe redesplegarse para que los leads nuevos usen el resolver. Si WordPress no envía ningún campo de nombre, el fallback sigue siendo Consumidor Final.

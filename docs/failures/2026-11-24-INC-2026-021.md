# INC-2026-021 - El desplegable de razon de perdida no muestra Cliente abandonado

- Fecha: 2026-11-24
- Flujo critico: R3
- Estado: CERRADO

## Impacto

En el detalle de una oportunidad, el select «Razón de Pérdida» no ofrecía «Cliente abandonado» (CRM_RazonesPerdida id 35, activa, creada 2026-11-24 12:49 -05) ni «INT - Cliente abandonado » (id 34, activa, con espacio final, creada 2026-11-20). La lista era la misma en PROPIO/B2C y en el resto de canales. No se modificó ninguna fila de Supabase.

## Causa raiz

`app/oportunidades/[id]/page.tsx` pintaba el array fijo `LOSS_REASONS`. No hay filtro por canal ni por prefijo: `CRM_RazonesPerdida` solo tiene `id`, `descripcion`, `is_active` y `created_at`. Los prefijos N-, RED- e INT- son texto de la descripción. Dexie recibe el catálogo en `hydrateReferenceCatalogsFromSupabase`, pero el select no lo leía, y el sync de catálogos no pedía esa tabla. Por eso una razón nueva activa no aparecía al recargar.

## Prevencion

El select lista las filas con `is_active !== false` y descripción no vacía, ordenadas por id (`selectLossReasonsForPicker`). El valor guardado es el `descripcion` exacto; la etiqueta se recorta. Al abrir el resumen se vuelve a leer Supabase y se reemplaza la copia local. Si no hay red, se usa Dexie. El refresh de catálogos del sync también reemplaza `lossReasons`. Una razón inactiva sigue oculta. Ocultar otra razón es poner `is_active = false`, no editar código.

## Deteccion permanente

- Prueba que falla antes de la correccion: `tests/lossReasonCatalog.test.ts` (no resolvía `@/lib/lossReasonCatalog`).

- Identidad estable del caso: `Razones de pérdida activas para el desplegable > incluye Cliente abandonado (35) y el INT con espacio final (34), y oculta inactivas`.
